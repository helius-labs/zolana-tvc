# zolana-tvc-protocol

Development protocol and cryptographic foundations for Zolana TVC wallets.

This crate is **not** a production verifier and **not** a funded wallet service.

See [`TVC Client Wallet Architecture`](../../apps/client-wallet/ARCHITECTURE.md)
for the current end-to-end component and trust boundaries. The normative rules
and formats are defined in
[`TVC_SPEC.md`](../../spec/TVC_SPEC.md).

## What this crate does

- versioned request/response/discovery types
- strict JSON parsing (unknown and duplicate fields rejected)
- RFC 8785/JCS for signed objects
- canonical decimal `u64` encoding
- domain-separated digest constructors
- `request_digest` that omits only `authorization.signature`
- P-256 client authorization: 65-byte uncompressed SEC1, 64-byte raw low-S `r || s`
- QOS P-256 envelope matching pinned `qos_p256 = 0.12.1` (`P256Public::encrypt`)
- independently pinned release-policy signatures (development 1-of-N; empty/duplicate/unknown keys fail closed)
- request bindings for release/manifest/executable/security domain/Quorum key
- bounded `/health` and `/v1/info` handlers
- named errors without secret-bearing messages
- committed content-addressed fixtures

## What this crate does not do

- production funds, Turnkey custody operations, or transaction broadcast
- AWS Nitro Boot Proof verification
- Turnkey `decisionContextDigest` linkage (evidence is `CryptographicallyValidButUnbound`)
- generic signing, wallet export, or a `Verified` result type
- claim that `/v1/info` is a trust root

`qos_p256 = 0.12.1` is a **test-only** AGPL-3.0-only dependency used to prove envelope compatibility. It is not a runtime dependency of this crate.

`/health` reports process readiness only. `/v1/info` is untrusted discovery.

## Fixtures

`fixtures/` is generated by the conformance tests and hashed in `fixtures/MANIFEST.json`. Rust and TypeScript clients must match these bytes.
